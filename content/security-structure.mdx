# 보안 3요소, CIA 원칙

정보 보안에서는 기밀성(Confidentiality), 무결성(Integrity), 가용성(Availiablity)이라는 세 가지 요소로 구성된 CIA 원칙이 있습니다.

기밀성은 허용된 사람만 정보에 접근/관리할 수 있는 것을 의미하고, 무결성은 정보가 변조되지 않는 상태를 유지할 수 있는지, 가용성은 이러한 정보가 원할히 제공될 수 있는 상태가 유지되는 지를 의미합니다.

일반적으로 기밀성과 무결성을 향상시키면 가용성은 상대적으로 낮아지게 됩니다.

이는 웹 서버에 SSL 인증서를 적용하는 경우를 생각하면 될 것 같습니다.

SSL 인증서를 도입하여 중간자가 원본 데이터를 읽지 못하게 만들고, 데이터가 변조되는 것도 방지할 수도 있습니다.

하지만 SSL 인증서가 만료되는 상황에서는 정상적인 사용자도 웹 서비스에 접근을 못하는 상황이 발생할 수 있습니다.

CIA 원칙에서 각 요소에는 고정된 우선순위가 없으며, 상황에 따라 적절하게 우선순위를 판단하는 것이 옳다.

# 방화벽

방화벽은 기본적으로 네트워크 세그멘트의 경계에 위치하게 됩니다.

방화벽은 패킷의 IP, 포트 번호, 패킷 정보 등을 확인해서 통과시킬지 결정하게 됩니다.

이러한 방화벽에도 처리 방식에 따라 아래와 같은 방식으로 나뉩니다.

## 패킷 필터링 방화벽 (Stateless)

패킷 필터링 방화벽은 OSI 7계층 중 3~4계층 패킷의 헤더를 바탕으로 트래픽을 필터링합니다.

네트워크 계층에서는 출발지 IP, 목적지 IP, 전송 프로토콜 유형을 필터링하고, 전송 계층에서는 출발지 포트와 목적지 포트를 필터링합니다.

이러한 5개 속성을 5-tuple이라고 부릅니다.

![](/content/firewall_osi_7layer_diagram_v5.png)

이러한 패킷 필터링 방화벽에는 단점이 존재합니다.

예시로 클라이언트 -> 방화벽 -> 서버 구성을 생각해봅시다.

방화벽 단에서는 80/TCP 포트로 들어오는 모든 요청에 대해서 개방하였습니다.

|출발지 IP|목적지 IP|프로토콜 유형|출발지 포트|목적지 포트|차단 여부|
|---|---|---|---|---|---|
|*|*|*|*|*|차단|
|*|서버_IP|TCP|*|80|허용|

이러한 구성에서 클라이언트가 http://서버_IP로 접속을 시도하게 되면 서버로 요청은 가지만, 이에 대한 응답은 방화벽에서 차단되는 문제가 발생합니다.

이는 해당 방식의 방화벽에서 요청 데이터를 기억하지 않기 때문에 응답 데이터는 다른 트래픽으로 보기 때문에 발생하는 문제입니다.  

## 상태형 검사 방화벽 (Stateful)

상태형 검사 방화벽은 요청 데이터에 대한 5-tuple 데이터를 테이블 형식으로 저장한다는 차이점이 있습니다.

요청에 대한 응답이 방화벽에 도달하게 되면, 상태 테이블과 비교하여 IP, 포트, 프로토콜 유형이 일치하는 경우 통과시킵니다.
