VPN이란 외부 인터넷 위에 가상의 전용 회선을 구축하는 것입니다.

외부 인터넷을 통해 통신이 이루어지기 때문에 중간에 경유하는 라우터들에서 트래픽이 지나간다는 것은 알 수 있지만,

트래픽 내 데이터들은 암호화되어 통신되기 때문에 데이터가 노출될 위험성이 없습니다.

위 설명과 같이 암호화를 통한 가상의 전용 회선 구간을 터널이라고 합니다.

이러한 VPN은 암호화가 적용되는 계층 및 방식 등에 따라 여러가지 유형으로 나뉩니다.
# IPsec

IPsec VPN은 주로 Site-to-Site 방식으로 사용되는 VPN입니다.

예시를 들자면 데이터센터(Site)와 회사(Site) 간 연결이 있겠습니다.

IPsec은 게이트웨이<->게이트웨이 간 통신시에 사용됩니다.

> 최종적으로 데이터를 송수신하는 종단 지점이 아닌, 트래픽을 라우팅해주는 장비들이 게이트웨이로 불립니다.

출발지 IP와 목적지 IP를 VPN 장비로 하여 IP 패킷을 새로 만들어냅니다.

새로 만들어진 IP 패킷 안에 원본 IP 패킷을 암호화하여 집어넣습니다.

1. 출발지 PC에서 보낸 원본 패킷이 출발지 VPN 장비에서 암호화되어 신규 IP 패킷으로 캡슐화됩니다.
2. 캡슐화된 패킷은 도착지 VPN 장비에 도달하게 됩니다.
3. 도착지 VPN 장비에 도달하게 되면 신규 IP 패킷을 벗기고 기존 IP 패킷을 복호화하여 도착지 PC로 라우팅합니다.

원본 IP 패킷을 암호화하여 새로운 IP 패킷으로 캡슐화하여 보내는 까닭은 외부 인터넷에 내부 네트워크의 정보(내부 IP 등)를 노출하지 않기 위해서입니다.

참고로 게이트웨이 간이 아닌 PC 대 PC로 직접 연결하는 Transport 방식도 존재하지만, 실무에서는 거의 쓰이지 않아 이 글에서는 다루지 않습니다.

# SSL VPN

SSL VPN은 SSL을 기반으로 암호화와 터널을 구현합니다.

보통 다수의 클라이언트가 하나의 VPN 장비에 연결되는 방식으로 구성됩니다.

1. 클라이언트에서 SSL VPN 장비의 SSL 인증서를 검증합니다.
2. VPN 클라이언트 앱에서 SSL VPN 장비로 ID, PW를 보내 인증합니다.
3. 양측에서 모두 검증이 이루어졌고, 이제 클라이언트에는 SSL VPN 통신을 위한 가상 NIC가 생성됩니다.
4. 클라이언트에서 가상 NIC를 통해 VPN IP로 요청을 보내면 가상 NIC에서는 이를 VPN 클라이언트 앱으로 보내 VPN 장비의 공인 IP로 된 패킷 내에 캡슐화합니다.
5. 캡슐화된 패킷을 실제 물리 NIC를 통해 VPN 장비로 전송합니다.

# 그래서 어떤 VPN을 선택해야 할까

IPsec과 SSL VPN 중 무엇을 쓸지는 "누가, 어떻게 접속하는가"에 따라 갈립니다.

## IPsec을 선택하는 경우

데이터센터와 회사 지사처럼, 두 네트워크가 상시로 연결되어 있어야 하는 경우에 적합합니다.

이런 연결은 특정 개인이 아니라 네트워크 전체가 대상이기 때문에, 게이트웨이 장비 간에 터널을 맺어두고 그 안의 모든 트래픽을 자동으로 암호화하는 방식이 효율적입니다.

한번 터널을 구성해두면 이후에는 사용자가 별도로 로그인하거나 클라이언트를 실행할 필요 없이, 두 네트워크가 마치 하나의 네트워크처럼 동작합니다.

## SSL VPN을 선택하는 경우

재택근무자나 외부 출장자처럼, 개별 사용자가 각자의 PC로 회사 내부망에 접속해야 하는 경우에 적합합니다.

이런 경우엔 사용자마다 인증(ID/PW)이 필요하고, 접속하는 위치나 네트워크 환경이 매번 다르기 때문에, 특정 네트워크 대역이 아니라 개별 클라이언트 단위로 연결을 맺는 SSL VPN 방식이 더 잘 맞습니다.

## 정리하면

- 네트워크와 네트워크를 잇는다 → IPsec
- 사람과 네트워크를 잇는다 → SSL VPN

같은 회사 안에서도 지사 간 연결은 IPsec으로, 재택근무자 접속은 SSL VPN으로 두 가지를 함께 운영하는 경우가 일반적입니다.
